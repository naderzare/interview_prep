# Algorithms: 0 → hero

**Use:** Start at 00 or jump to a weak spot → cover its template → name the recognition clues and invariant → trace its tiny example → try one anchor problem. The numbers give a suggested path from simpler patterns to harder ones, not a mastery score. For a quiz, ask the algorithm coach; it should hide the technique until you make a guess.

| Step | Topic | First question to ask |
| --- | --- | --- |
| 00 | [Hashmap](00-hashmap.md) | Do I need fast lookup or counts of what I saw? |
| 01 | [Two pointers](01-two-pointers.md) | Can two positions move toward an answer? |
| 02 | [Sliding window](02-sliding-window.md) | Is the answer a contiguous range? |
| 03 | [Binary search](03-binary-search.md) | Is there a sorted order or monotone yes/no test? |
| 04 | [Recursion](04-recursion.md) | Is the same problem nested inside a smaller one? |
| 05 | [Trees](05-trees.md) | Does each node split into child subproblems? |
| 06 | [Heap](06-heap.md) | Do I repeatedly need the smallest/largest live item? |
| 07 | [Graphs](07-graphs.md) | Must I explore connections, cycles, or reachability? |
| 08 | [Backtracking](08-backtracking.md) | Must I explore choices and undo them? |
| 09 | [Dynamic programming](09-dynamic-programming.md) | Do smaller answers repeat and combine? |

Each card has a quick recognition cue, a core template, a variation guide, and two tiny examples. Choose the variation before coding. Keep [session notes](notes.md) to two short lines per session.
